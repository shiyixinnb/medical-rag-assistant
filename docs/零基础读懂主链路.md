## 0. 先建立 4 个概念

### 0.1 大模型（LLM）= 一个"根据上文补下一个词"的函数

```
输入：一段文字（prompt）
输出：一段文字（回答）
```

它有三个必须记住的特性，这个项目的很多设计都是为了应付它们：

| 特性 | 后果 | 项目的应对 |
|---|---|---|
| 没有你的数据 | 不知道院内制度、不知道这个病人的病历 | RAG（先去查资料） |
| 会编（幻觉） | 没查到也会硬答，而且答得很像真的 | 检索为空就拒答，不交给模型 |
| 每次调用都失忆 | 记不住上一轮说了什么 | 会话存 Redis，每次把历史一起发过去 |

**幻觉的准确定义**：模型输出了看起来合理、但资料里没有的内容，而且它不会报错。类比：一段不抛异常、只是默默返回了错误数据的代码——最难查。

### 0.2 embedding = 语义版的 hashCode

把一段文字变成一组固定长度的数字（本项目 **1024 个 float**）。

- `hashCode()`：相等 → 相同；不相等 → 可能撞车，但**绝不表示"意思接近"**。
- `embedding`：**意思接近 → 数字接近**。

举例（示意）：

```
"被狗咬伤了怎么办"   → [0.12, -0.33, 0.08, ...]
"犬咬伤的处理流程"   → [0.11, -0.31, 0.09, ...]   ← 距离很近
"今天天气不错"       → [-0.72, 0.44, 0.51, ...]  ← 距离很远
```

⚠️ **建库和检索必须用同一个 embedding 模型**。换模型 = 换了一套坐标系，旧向量全部作废，必须重建索引。

### 0.3 向量检索 = ORDER BY 距离 LIMIT k

```sql
-- 你熟悉的写法
SELECT * FROM knowledge WHERE title LIKE '%狗咬%' LIMIT 4;

-- 向量检索干的事
SELECT * FROM knowledge ORDER BY distance(问题向量, 资料向量) LIMIT 4;
```

区别在于：`LIKE` 只能匹配字面，换个说法就查不到；向量比的是"意思"。

本项目的两个参数（`application.yml` → `app.llm.rag`）：

| 参数 | 值 | 含义 | 调大的后果 |
|---|---|---|---|
| `top-k` | 4 | 最多取几条 | 上下文变长、更贵、更慢，还可能引入噪声 |
| `similarity-threshold` | 0.5 | 相似度低于它就不要 | 调太高会"什么都查不到"，回答变成"资料不足" |

### 0.4 RAG = 开卷考试

不让模型凭记忆答，而是：

1. 先把问题相关的资料查出来；
2. 把资料塞进 prompt；
3. 要求模型"只根据这些资料回答，并标注出处"。

两个阶段必须分清：

- **离线建库**：MySQL 资料 → 切段 → 算向量 → 存 Redis。知识变更时跑一次。
- **在线问答**：问题 → 算向量 → 检索 → 拼 prompt → 模型 → 校验输出。每次提问都跑。

## 1. 一条请求的一生

入口：`ClinicalAssistantController.ask`（L78）→ `ClinicalAssistantService.ask`（L119）。

`ask` 只有 13 行，真正的内容在 `prepare()` 里：**它把所有"不该让模型决定的事"提前做完**。

### 1.1 prepare() 逐行翻译

| 行号 | 代码在做什么 | 大白话 | 删掉会怎样 |
|---|---|---|---|
| L221-227 | 校验 question、读 tenantId | 空问题直接报错 | 空字符串会走完整条链路，白烧 token |
| L230 | `conversationStore.loadOrCreate` | 把这轮对话的历史捞出来 | "那它的剂量呢"变成无头问题 |
| L233 | `intentClassifier.classify` | 判断这句话属于哪类问题 | 不知道该不该碰患者数据，只能全放开或全拒 |
| L239 | `shouldClarify` | 问题太笼统就先追问 | 用户说"怎么办"，系统直接给一个可能不对的剂量 |
| L253-268 | 授权判定 + **fail-closed** | 没带 tenantId 就当作没权限，直接拒 | 任何人不带参数就能查病历 |
| L270-274 | 组装要查的数据域 | 决定查公共域，还是连患者域一起查 | — |
| L279 | `patientIdExtractor` | 从问题里抓出 `P-1001` 这种编号 | 拿 A 医院的授权能查到 B 医院的患者，且靠模型自己"发现"（不可靠） |
| L282 | `retriever.retrieve` | 真正去向量库查资料 | 模型只能靠记忆编 |
| L287-301 | 检索为空 → 拒答 | 没资料就不答 | 模型会"努力回答"，这就是幻觉的主要来源 |
| L304-309 | `promptService.buildSystemPrompt` | 把规矩、资料、格式要求拼成纸条 | 模型不知道要引用、不知道输出格式 |

### 1.2 关键：为什么顺序不能换

```
意图 → 授权 → 检索 → Prompt → 模型
```

因为**后一步的输入依赖前一步的结论**：

- 不知道意图，就不知道要不要碰患者域 → 授权无从判断；
- 没有授权，就不能去检索（fail-closed 要求"连查都不查"）；
- 没有检索结果，Prompt 里就没有资料，也就无法判断"该不该拒答"。

而且这条顺序体现了一个设计前提：**安全判断全部排在"调模型"之前**。模型是整条链路里最贵、最慢、最不可控的一环，能让它不跑就不跑。

## 2. `escapeTagValue()` 到底在转义什么

这是全项目最"反直觉"的一段代码，值得单独讲。

### 2.1 背景：过滤条件长什么样

患者域的检索，实际发给 Redis 的是一句查询：

```
@domain:{PATIENT} @tenantId:{HOSP-A}
```

`@tenantId:{...}` 是 RediSearch 的 **TAG 语法**：花括号里是一个标签值。

### 2.2 问题：`-` 是分隔符

RediSearch 的查询解析器把 `- . : , ( ) 空格` 等都当成**标点分隔符**。所以：

```
你想要的：  @tenantId:{HOSP-A}        ← 一个值 "HOSP-A"
它理解的：  @tenantId:{HOSP} - {A}    ← 两个东西，而且语法不合法
结果：      Syntax error at offset 21 near A
```

### 2.3 解法：给特殊字符加反斜杠

```
转义后：    @tenantId:{HOSP\-A}
结果：      正确命中，过滤生效
```

`escapeTagValue()`（L253-270）就是这个规则的手写实现：

```java
for (每个字符 c) {
    if (c 是中文等非 ASCII)   → 原样保留;
    else if (c 是 a-z A-Z 0-9 _) → 原样保留;
    else                      → 前面加一个 '\';
}
```

举例：

| 原值 | 转义后 |
|---|---|
| `HOSP-A` | `HOSP\-A` |
| `P-1001` | `P\-1001` |
| `市一院` | `市一院`（中文不动） |

⚠️ **中文一定不能转**。实测 `\院` 这种写法会让 RediSearch 命中 0 条，因为它对非 ASCII 字符没有转义语义。

### 2.4 为什么这个 bug 特别阴险

Spring AI M7 的 `RedisFilterExpressionConverter` **不做任何转义**，直接把值拼进 `{...}`。而这个失败有两种形态：

| 失败形态 | 表现 | 危险程度 |
|---|---|---|
| `HOSP-A` | 报 `Syntax error`，日志里有 | 低，能发现 |
| `P-1001` | **不报错，静默命中 0 条** | 高，容易被误判成"知识库本来就没这条" |

第二种是最坑的：功能看起来正常，只是永远查不到东西。

> 一句话记法：**带连字符的 ID = 必须转义；中文 = 绝对不能转。**

## 3. 三层防御（为什么"过滤"还不够）

`DomainAwareRetriever` 的类注释里写了三层，用机房打比方：

| 层 | 代码位置 | 类比 | 作用 |
|---|---|---|---|
| ① 物理隔离 | L106-107 选 `patientStore` | 没权限的人**根本进不了机房** | 未授权的域，对应的 VectorStore 压根不调用 |
| ② 索引过滤 | L215-234 `buildFilter` | 进了机房，但 SQL 里带 `where tenant_id=?` | 只把本租户的数据捞出来 |
| ③ Java 复核 | L113-141 | 数据拿回来，**逐行再核对一遍**租户 | 兜底：索引坏了、过滤没生效时拦住 |

第 ③ 层正常情况下**应该永远丢弃 0 条**。一旦日志出现 `跨租户片段已被丢弃`，就说明 ①② 层出了问题——它是报警器，不是常规流程。

这就是 **fail-closed** 的含义：拿不到授权信息时当作"没权限"，而不是"不限制"。反过来写（"参数为空就跳过过滤"）就是数据泄漏事故的经典成因。

## 4. 术语表（Java 后端视角）

| AI 术语 | 一句话解释 | Java 里对应的东西 |
|---|---|---|
| Prompt | 发给模型的完整输入文本 | 一次方法调用的入参 |
| Token | 模型处理文本的最小单位，约 1 汉字 ≈ 1-2 token | `String.length()` 但更贵 |
| embedding | 文字 → 定长浮点数组 | 语义版 `hashCode()` |
| 向量库 | 存向量并支持"按距离查"的数据库 | 带 `ORDER BY distance` 的索引表 |
| top-k | 取最相近的 k 条 | `LIMIT k` |
| RAG | 先查资料再让模型答 | 开卷考试 |
| 幻觉 | 模型编造但看着合理的内容 | 不抛异常的脏数据 |
| Prompt 模板 | 带占位符的提示词文件 | Thymeleaf 模板 |
| 意图路由 | 按问题类型选处理方式 / 选模型 | `switch (type)` 分派 handler |
| 熔断 | 连续失败就暂停调用它 | Sentinel |
| 降级 | 主模型挂了换备用 | 主库挂了读从库 |
| 会话 | 多轮对话的上下文 | `HttpSession`，但存 Redis 以支持多实例 |
| SSE | 服务端边生成边推送的 HTTP 响应 | 分块下载，服务端不关连接 |
| Meta 行 | 模型额外输出的一行结构化信息 | 响应体里的 header 字段 |

## 5. 读完自测（答案在文末）

1. 为什么"检索为空"必须拒答，而不能让模型"尽量回答"？
2. 建库换了 embedding 模型，为什么必须重建索引？
3. `tenantId` 不传时，患者域的问题会被怎么处理？模型被调用了吗？
4. `P-1001` 经过 `escapeTagValue()` 之后长什么样？为什么不能把中文也转义？
5. 三层防御里，第三层正常应该丢弃几条？如果丢弃了说明什么？

<details>
<summary>答案</summary>

1. 因为模型没有"我不知道"的可靠机制，检索为空时它仍会生成看似合理的内容——这就是幻觉。拒答是确定性的，幻觉不是。
2. embedding 换了模型就换了一套向量空间，新旧向量不可比较，必须用新模型重算全部资料。
3. 按 fail-closed 直接拒答，`modelId=none`，连向量库都不会查。
4. `P\-1001`；中文不是 RediSearch 的转义字符，加反斜杠会让它无法匹配。
5. 0 条。出现丢弃说明索引过滤或物理隔离失效了，是异常信号，需要立刻排查。

</details>
